Tools

Command-line interface

gzim is the native runtime, checker, REPL, project bootstrapper, and compatibility exporter.

Run a program

gzim app.gzim [arguments...]
gzim run app.gzim [arguments...]

Both forms parse, semantically check, and execute the program in the current native process. Arguments are exposed through the global args stack.

Check a program

gzim check app.gzim

Runs the lexer, parser, and semantic analyzer without executing the program. A successful check exits with status 0. Caps exit nonzero and include file, line, and column information.

Start the REPL

gzim repl

Enter code at vibe>. A blank line executes the accumulated session. Ctrl+D exits.

Initialize a project

mkdir my-vibe && cd my-vibe
gzim init

Creates a starter main.gzim and gzim.toml without replacing existing files.

Manage packages

gzim add cool https://github.com/example/cool.git#v1.0.0
gzim install
gzim packages
gzim remove cool

Dependencies are project-local and may come from Git or a local directory. See Packages and projects.

Inspect the runtime

gzim doctor

Prints the installed version, confirms that the runtime is native and Python-free, and shows the compiled target OS and CPU.

Print the version

gzim --version

Optional Python export

gzim emit-python app.gzim

Writes app.py and a source map for interoperability with existing Python ecosystems. This command is optional: normal execution never invokes this backend. The legacy spelling gzim build remains as a compatibility alias in 2.0.

Export is not native execution

The generated file requires Python if you choose to run it. Use gzim app.gzim for the standalone Genzimnify runtime.

Exit codes

CodeMeaning
0Program or command completed successfully.
1Syntax, semantic, runtime, file, or CLI error.
Customsystem.exit(code) exits with the requested status.

Compatibility executable

Release packages use gzim. Source builds also keep gzimc for existing integrations; it routes to the same native CLI.
