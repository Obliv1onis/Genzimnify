Concepts

Native runtime architecture

Genzimnify 2.0.1 executes programs inside its own compiled runtime. The Python emitter and explicit py.* bridge exist for interoperability, but neither is part of normal native execution.

Execution pipeline

Lex

The native lexer turns source text into tokens, including indentation boundaries and multi-word slang.

Parse

A recursive-descent and Pratt parser builds a typed Genzimnify abstract syntax tree.

Vibecheck

Semantic analysis validates scopes, locks, assignment targets, function context, and control flow.

Execute

The native runtime evaluates the checked AST with Genzimnify values, environments, functions, cliques, modules, and exceptions.

Python dependency behavior

gzim run does not write a temporary Python script, invoke python3, load libpython, or use Pyodide. Release packages contain a native binary built from the Nim implementation.

The active runtime is reported by:

gzim doctor
# runtime: native Nim (Python-free)

Runtime values

The runtime implements its own none, truth, integer, float, text, stack, crew, squad, map, function, native cook, clique, instance, module, exception, and file-handle values. Operators and methods dispatch against those values directly.

Scopes and closures

Every cook captures its defining environment. Calls create child scopes, while worldwide and localish redirect assignments to global and enclosing scopes. lock bindings reject reassignment at both semantic-check and runtime layers.

Module loading

Native modules are registered by the runtime. Other names resolve to local .gzim files and execute inside isolated module environments. The module cache prevents repeated execution and supports imports relative to the current file.

Compatibility backend

gzim emit-python uses the older emitter on demand. Keeping that backend is useful for migration and ecosystem bridges, but a Genzimnify installation and ordinary Genzimnify programs are independent of it.

2.0.1 scope

The native release covers arithmetic, collections and comprehensions, functions and generators, cliques and inheritance, exceptions, matching, modules, packages, slices, type hints, glow strings, and timing syntax. Work still planned includes a full event loop, a central package registry, and optimized bytecode.

Runtime ownership

The lexer, parser, semantic checker, values, module loader, and evaluator are implemented in the Genzimnify runtime. The Python emitter and bridge are separate interoperability paths.
